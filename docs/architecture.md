# Architecture

Nemo is a **TypeScript monorepo**: one root `package.json` compiles the
whole `apps/` + `packages/` + `nemo/` tree into `dist/`, and the release build
ships on npm as `@shrijanagain/nemo-cli`.

## Repository layout

| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `apps/runtime/`                                                                                 | **Agent runtime**: `config.ts` (all config/env handling), `agent/agent-loop.ts` + `agent/agent.ts` (the loop; budget enforcement via `config.budget` → `budget_exhausted`), `tools/` (file edit, command exec, MCP, skills, memory, planning, checkpoint/rewind, web), `prompt/` (system prompt + corpus), `update/` (auto-update), `developer-mode/`, `checkpoints.ts`                                                                                                                                                                                                                                                                                                                                                          |

One caveat on `nemo/`, because its markdown is injected into the system prompt
and therefore reads as live behaviour: the **points / penalty / reward /
reliability** machinery is not implemented. `points.ts`, `penalty.ts`,
`reward.ts` and the `13-healing` subtree were deleted after being found to have
no callers, and the `.py` helpers left beside the data files (`points.py`,
`PENALTY.py`, `reward.py`, `eval.py`) are invoked by no CLI path, hook or
workflow. The `nemo/10-upload/` uploader is likewise gone — it was the only
egress path out of `nemo/`. What genuinely runs from `nemo/` is mistake memory
(`1-errors/mistake.ts`), the chain-of-thought engine (`5-eval/cot.ts`,
`cot-chain.ts`), improvements logging (`6-u/improvements.ts`, prompt-instructed
rather than imported), hooks (`14-hooks`) and the context assembler.
`0-points/points.md`, `5-eval/EVALS.MD`, `1-errors/FRAMEWORK.MD` and
`7-cli/CLI.MD` carry explicit notes saying their scoring language is historical.

## Runtime data flow

```
nemo  (bin shim → dist/apps/cli/src/index.js)
   │  parseFlags()  →  loadConfig()            apps/runtime/src/config.ts
   │                    (defaults < file < NEMO_* env < flags)
   │
   ├─ subcommands (config/doctor/exec/web/acp/mcp/…) run directly
   │
   └─ run/chat: spawn packages/tui/src/repl/ink-repl.mjs  (ESM child)
         env: NEMO_CONFIG_JSON, NEMO_PROMPT, NEMO_MODEL, …
              │
              └─ ink-app/App.tsx  ── Agent (apps/runtime/src/agent)
                                       │  tool loop: bash/read/edit/grep/…,
                                       │  mcp__* tools, skills, planning
                                       ├─ packages/provider (wire formats)
                                       └─ events → TUI + transcript
                                                   (packages/session-backends)
```

The REPL is the _only_ interactive UI; the CLI hands it the resolved config
via `NEMO_CONFIG_JSON` so the child never sees `undefined` fields.

## Build pipeline

Three steps, all wired into `npm run build`:

| Step                | Command                                                          | Output                                                                                                                                                                                                                                                                                  |
| ------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Main compile     | `tsc -p tsconfig.json --noEmitOnError`                           | `dist/` — CommonJS, ES2022, `jsx: react`. Covers `apps/**`, most of `packages/**`, `nemo/**`. **Excludes** `packages/tui/src/ink-app/**`                                                                                                                                                 |
| 2. Ink compile      | `npm run build:ink` → `tsc -p tsconfig.ink.json --noEmitOnError` | `dist/packages/tui/src/ink-app-esm/` — NodeNext **ESM**, `jsx: react-jsx`. Only `ink-app/**` + `ui/theme.ts`                                                                                                                                                                            |
| 3. Assets + flatten | inline `node -e` step, then `require('./fix-esm-imports.js')`    | copies `EVALR.MD`, `mistakes.json`, `evals.json`, `EVALS.MD`, `ink-repl.mjs`, `logo_ansi.txt`, `prompt/corpus.txt` into `dist/`, flattens the ESM tree to the output root, drops the nested `packages/ apps/ nemo/ ink-app/` dirs, and writes `{ "type": "module" }` into the ESM folder |

Supporting scripts (root `package.json`):

| Script                            | What it does                                                                                                                                                                                                                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `npm run typecheck`               | `tsc -p tsconfig.check.json` — noEmit + incremental twin of the main config                                                                                                                                                                                                                     |
| `npm run typecheck:ink`           | `tsc -p tsconfig.ink-check.json` — same for the Ink app                                                                                                                                                                                                                                         |
| `npm run build:loose`             | Emit-only build (`--noCheck`) for a fast local smoke run                                                                                                                                                                                                                                        |
| `npm run lint`                    | `eslint apps packages nemo` (flat config in `eslint.config.mjs`; no `--ext`)                                                                                                                                                                                                                     |
| `npm run format` / `format:check` | Prettier                                                                                                                                                                                                                                                                                        |
| `npm test`                        | `vitest run` (`vitest.config.ts`); coverage: `npx vitest run --coverage` (`@vitest/coverage-v8`)                                                                                                                                                                                                |
| `npm run sbom`                    | CycloneDX SBOM → `sbom.cyclonedx.json`                                                                                                                                                                                                                                                          |
| `npm run publish:build`           | `npm run build` + `scripts/make-publish.mjs` — copies to `publish/`, obfuscates JS (skip with `NEMO_SKIP_OBFUSCATION=1` or `--skip-obfuscation`), adds the `node` shebang, writes `publish/package.json` (`@shrijanagain/nemo-cli`, `files: ["dist","Img"]`, bins `nemo` + `nemo`) |
| `npm run publish:npm`             | publish build + `npm publish ./publish --access public --provenance`                                                                                                                                                                                                                            |

Two tsconfigs exist on purpose: the emitting one avoids `incremental` (a
deleted `dist/` file would otherwise never be regenerated), and the check-only
twin keeps `npm run typecheck` fast without touching `dist/`.

## CI (`.github/workflows/ci.yml`)

| Job                      | Commands                                                                                                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Typecheck + version sync | `npm run typecheck`, `npm run typecheck:ink`, `npm run sync-version` + `git diff --exit-code` on `apps/cli/src/version.ts`                                        |
| Lint + format            | `npm run lint`, `npm run format:check`                                                                                                                            |
| Tests                    | `npm run test` on Node **18, 20, 22** (Ubuntu) + Node **20** on **Windows** and **macOS** (5 legs)                                                                |
| Coverage thresholds      | `npm run test:coverage` (uploads `coverage/` artifact)                                                                                                            |
| Build                    | `npm run build` + `--version` smoke on Ubuntu **and Windows**; Windows also smoke-tests the `bin\nemo.cmd` / `bin\nemo-code.cmd` shims (stale-dist detection path) |
| Publish tarball audit    | `NEMO_SKIP_OBFUSCATION=1 npm run publish:build` then `npm run verify:pack`                                                                                   |
| Audit + SBOM (blocking)  | `npm audit --omit=dev --audit-level=high`, `npm run sbom` (SBOM uploaded)                                                                                         |
| Schema + docs            | `config.schema.json` / `docs/README.md` / `LICENSE` exist, the schema parses, and `npm run check:links` proves every internal doc link + anchor resolves          |
| Codespell                | spell-check over the repo                                                                                                                                         |

`.github/workflows/release.yml` (tags `v*`) additionally gates on
tag ↔ `package.json` version equality, blocks on the SBOM, verifies the
tarball with `verify:pack` before `npm publish --provenance`, and creates
a GitHub Release with generated notes.

## Design notes

- **Apache-2.0 license, all source headers**: every `.ts` file starts with
  the Apache-2.0 header (see `LICENSE`).
- **Config is validated, never fatal**: bad MCP servers, hooks, model caches,
  and keys are sanitised at load (`sanitizeConfig`, `cleanMcpServers`,
  `cleanToolHooks`, `cleanApiKey`) instead of crashing later.
- **Transcripts are append-only** and written best-effort — a disk error must
  never break a turn.
- **Headless mirrors the REPL**: `exec`, `web`, `acp`, and the SDK all drive
  the same `Agent` from `apps/runtime`, so behaviour matches the interactive
  session.
