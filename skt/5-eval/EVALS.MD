# SKT AI LABS - Evaluation History

Auto-regenerated by `5-eval/eval.py`. Every evaluation cycle appends a new section here. The agent reads this file before each task to decide whether to apply bonuses or restrictions.

## How to read this file

- A `reliability` ≥ 0.8 means the assistant is performing well — reward bonuses apply.
- A `reliability` < 0.5 means the assistant is repeating mistakes — the task-type is restricted.
- A row with `note: HIGH reliability` triggers the bonus path in `6-u/reward.py`.
- A row with `note: LOW reliability` triggers the restriction path in `0-points/points.ts`.

## Schema

```
## TIMESTAMP (ISO 8601)
- reliability: float in [0, 1]
- improvements: count of IMPROVMENT.MD entries in the last 30 days
- repeats: count of 2nd-mistake.md entries in the last 30 days
- by_type: JSON map of task_type → weighted score
- note: optional annotation from the eval engine
```
